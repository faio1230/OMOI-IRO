# OMOI-IRO PRD

## 目的と利用者

DJ Mixを制作・演奏する本人が、Launchpad XをLiveの操作デバイスとLED演出面として利用する。曲に合わせた演出を保存・編集し、共通タイムコードに沿う演出と拍に反応する演出を重ねる。新しい機器やエフェクトを追加しても既存ショーを保守できることを重視する。

最初の利用環境はAbleton Live 12 Suite、Launchpad X 1台、Windows 10/11の候補環境またはApple Silicon Mac。具体的な対応OS版は検証後に確定する。ハードウェア未接続でも同じショーをシミュレーターで編集・再生できる。

## 確定した運用条件

ArrangementとSessionを初期から同じ受け入れ基準で扱う。Sessionの演出はセット全体の共通タイムコードに追従し、クリップ起動ごとにはリセットしない。Launchpad XはアプリがProgrammer Modeで管理する。Liveへ操作を転送し、必要な割り当てはLiveのMIDI Mapで行う。

Liveを音楽の再生マスターとする。本番追従中にアプリが独自のテンポや再生位置でLiveを駆動することはない。ローカル再生・スクラブはシミュレーター用として明示する。

## 主な利用フロー

1. Launchpad、Control、TimecodeのポートとLink接続を設定する。MIDI Clock方式を選ぶ場合はClockポートも割り当てる。
2. ショーを開き、タイムライン上に演出クリップを配置する。色、開始時刻、長さ、不透明度を編集する。
3. プレビューで時刻を移動して、重なりや切替を確認する。
4. Liveで再生する。両ビューで共通タイムコードと拍に追従し、入力はLiveへ届く。
5. プリセットを保存して別のクリップやショーで再利用する。
6. 終了時に必要なNote Offと消灯を送信し、Launchpadを通常モードへ戻す。

## MVPの機能要件

| ID | 要件 | MVPの具体的な範囲 | 受け入れ条件 |
| --- | --- | --- | --- |
| FR01 | RGB LED制御 | LPX 1台、64パッド、30 fps目標、明るさ・Blackout | 指定色と座標が実機に一致、復帰時に全体再送 |
| FR02 | MIDI入力とLiveへの転送 | Note On/Off、CC、固定ルート、基本フィルター | 押下・解放を重複なくLiveへ転送、ループなし |
| FR03 | MTC受信 | Quarter Frame、Full Frame、24/25/29.97 DF/30、offset | 正常系列・不連続・欠落を識別し、誤った時刻を採用しない |
| FR04 | タイムライン演出 | 秒単位クリップの追加・移動・長さ・複製・削除 | 任意の位置へ移動した結果が連続再生の同位置と一致 |
| FR05 | BPM・拍の演出 | Linkを優先候補、MIDI Clockも選択可能。BPM/四分音符位相、Pulse | テンポ変更に追従、途中参加と接続喪失を識別。Liveのtempoを上書きしない |
| FR06 | LEDレイヤー合成 | 順序、不透明度、over/add/max、8レイヤーを基準負荷 | 順序と数式が明確で、プレビューと出力が同じフレームを使用 |
| FR07 | プレビュー | 同じRustエンジンの出力、仮想LPX、ローカル時計 | 機器なしで編集・再生・シーク可能 |
| FR08 | プリセット | Solid、Chase、Pulseのパラメーター保存・読込 | 保存・再読込で値と結果が変わらない |
| FR09 | バージョン管理 | JSON、Schema、固定ID、安定した整形 | 無変更の再保存で無意味な差分を出さない |
| FR10 | 状態と復旧 | ポート、同期品質、遅延、破棄数、Blackout、再接続 | GUI操作遅延や接続断が入力処理を巻き込まない |
| FR11 | 両ビューでの利用 | 共通タイムコードを追跡 | Sessionのクリップ変更とビュー切替で勝手に時刻をゼロにしない |

初期クリップは秒単位で配置し、拍同期はPulseの位相に使う。拍数をキーとするタイムライン編集、テンポマップ編集、小節単位の正確な復元は後続段階に分ける。入力のaftertouch等は未知メッセージとして破損なく識別・診断できるようにし、Liveへの転送は明示設定した場合に拡張する。

## UIの範囲

| 画面 | 必須操作 |
| --- | --- |
| 接続と同期 | 役割別ポート選択、疎通、MTC fps/offset、Link/Clock選択・状態、再接続 |
| ショー編集 | クリップとレイヤー一覧、タイムライン、数値編集、Undo/Redo |
| エフェクト編集 | 種類・色・速度・不透明度、プリセット保存・適用 |
| プレビューと演奏 | 8×8表示、共通時刻、ローカル/外部追従切替、Blackout |

波形表示、音声再生、映像プレビューは含めない。再生中の編集は検証済みの変更単位で反映し、演奏中に壊れたデータを読み込ませない。

## 非機能要件と計測条件

以下は初期目標であり実測値ではない。S01〜S07の測定後に対応環境と数値を確定する。

| ID | 項目 | 目標・測定方法 |
| --- | --- | --- |
| NFR01 | Core独立性 | Tauri、WebView、midirなしでCoreのテストと任意時刻renderが実行可能 |
| NFR02 | 入力処理遅延 | MIDI callback受領からLive向けsend開始までp95 5 ms以下。OS入口前とsend後の遅延は別計測 |
| NFR03 | 描画負荷 | 64パッド、8レイヤー、30 fpsでrender p95 5 ms以下。テストPCとショーを固定して測定 |
| NFR04 | LED更新 | 30 fpsを基準に10分間測定。欠落・送信待ちの分布を記録し、無制限キューを作らない |
| NFR05 | 同期誤差 | 30 fps MTC、ロック後、固定遅延補正後の推定位置誤差p95 1 frame以内を初期目標。UI表示値を測定基準にしない |
| NFR06 | 復帰 | 正常MTCが戻ってから500 ms以内の再ロックを初期目標。Full Frame位置反映と再生判定は分ける |
| NFR07 | 長時間動作 | 両OSで2時間の連続動作を最終目標とする。メモリーの継続増加、stuck note、累積同期ドリフトなし。Macは放置不可のため初期は短時間の立ち会い試験を分割実施し、連続試験は未検証として別管理 |
| NFR08 | 決定性 | 同じshow revision、時刻、拍状態、seed、overrideに対し同じRGB7結果。OS間差は量子化後±1以内を目標 |
| NFR09 | データ保全 | 構造・意味検証後に読込、一時ファイルからの安全な置換保存、失敗時は元データを維持 |

LEDの物理応答と音声とのずれは、MIDI時刻推定の精度とは分けて測定する。必要に応じ動画撮影やフォトセンサー等で評価する。初期MVPはフレーム精度のLED演出を対象とし、音声サンプル精度は受け入れ条件に含めない。

## 障害時の仕様案

- 初回起動は出力未接続。ポートを選び、接続操作を行ってから機器を制御する。
- 正常なStopは最後のフレームで停止。Blackoutでいつでも消灯できる。
- MTC未受信は消灯。受信中断時は短時間だけ補間し、最終受信から1秒で消灯する案とする。
- LinkまたはClockの拍同期だけ失われた場合、時間ベース演出は続け、拍演出は保持後に消す。別の拍入力やBPMへ自動切替しない。
- USB切断後もシミュレーターと編集は継続。再接続時はモード確認と全フレーム送信を行う。
- BlackoutはLEDにだけ作用する。DJ操作の転送を止める機能は別にする。
- 安全上限（2026-10-28追加、端末設定）：LED送信直前に各チャンネルを輝度上限でクリップする。Pulse / Chaseの点滅周波数を静的に計算し、上限（既定3 Hz）を超える演出には編集画面と演奏画面で警告する。利用者が明示した場合だけ該当レイヤーを消灯し、演出データは書き換えない。

保持時間等は[設計判断](07-decisions.md)に記載した初期提案値。

## 後続の拡張

F1、複数機器、ノードエディター、MIDIマッピングGUI、OSC、他DAW、外部プラグインはMVP完成後に追加する。静的なTrigger/Actionの境界は初期から設けるが、汎用ワークフローやプラグインホストは実装しない。

リアルタイムに手動で加えた操作やテンポ変化を、時刻だけから完全復元することはできない。MVPは時間ベースの演出を時刻から再現し、拍演出は同じ拍状態から再現する。演奏全体の完全な再現が必要になった段階で、入力・テンポ・overrideの記録再生を追加する。

## MVPの完了条件

FR01〜FR11のデモと、Windows/macOS双方の接続・同期・復旧試験を完了する。サンプルショーをGit差分でレビューでき、機器なしでも同じ編集データを開ける。Sessionだけ、またはシミュレーターだけで成功した状態を全体MVPの完了としない。

Macの短時間試験を通過した段階は「機能検証済み・連続安定性未検証」として扱い、設計調整と開発を進められる。最終的な本番利用の判定では、NFR07の連続試験結果を別途確認する。利用者不在のMac実機運転は計画しない。
