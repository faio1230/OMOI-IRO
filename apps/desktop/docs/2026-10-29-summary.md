## 素材バンク（Schema 0.1.4）

- Schema は **0.1.4**。追加は preset / compound の `metadata: MaterialMetadata { category, tags, favorite }` だけ。0.1.0〜0.1.3 は読込時に版番号だけを書き換える。0.1.4 のファイルは旧ビルドでは読めない。
- 編集：`EditCommand::SetMaterialMetadata`（カテゴリ 48 文字、タグは各 32 文字・24 個まで）。描画には影響しない。
- サムネイル：`omoiiro_runtime::material_preview::sample(show, kind, id)`。セッション・ポート・時計に触れない隔離ショーで 24 コマを描く（模擬入力つき、毎回同じ結果）。desktop の command は `material_preview`（編集中のショーのスナップショットを worker で描く）。
- GUI：`apps/desktop/src/MaterialBrowser.tsx`。検索・カテゴリ・タグ・お気に入り・12 件ごとのページ。サムネイルは既定で静止し、「サムネイルを動かす」で動く。OS のアニメーション設定には依存しない（a9b4985）。
- 入力履歴（同じ fa4bf74）：`PadState` / `ScopedPads` の累計回数、`Renderer::configure_input` / `inherit_live_input`、録音の有界マージ（BinaryHeap）と `history::recording_until`。cycle の色番号は累計回数から決める（7cdbc98 で減算を飽和に）。
- QA 記録：[material-bank-qa.md](material-bank-qa.md)。

## 共通ライブラリー（A20）

- ライブラリー = 普通の `.show.json`。登録したショーの presets / compounds を一覧し、使うときに編集中のショーへ複製する。ライブラリーファイルは読むだけで書かない。
- 登録先：端末設定 `TerminalSettings.library_shows`（`crates/omoiiro-runtime/src/settings.rs`、`#[serde(default)]`、前後の空白を除き、重複なし、最大 `MAX_LIBRARY` = 10）。設定の version は据え置き。`settings_save` はフォームから受け取らず、現在値を保持する（`recent_shows` と同じ）。
- core：`EditCommand::InsertCompound { compound, presets, on_conflict }`（`crates/omoiiro-core/src/edit.rs`、履歴ラベル「ライブラリーから読み込み」）。
  1. 内側が参照する preset を先に取り込む。既存と同じなら再利用し、ID が衝突したら Rename。
  2. compound の layer / clip ID を、ショー全体で一意になるよう付け替える（`rename_on_conflict`）。preset 参照は 1 の対応表で書き換える。
  3. 同じ compound が既にあれば追加しない。なければ追加し、ID が衝突したら Rename。
- 重複判定：`same_preset` / `existing_preset`。name と effect が等しく、ID が同じか付け替え後の形 `<id>-N`。metadata は比べない。compound は内側の layer / clip ID を無視して比べる（`same_compound`）。付け替え後の形も同じと見るのは、再取り込みのたびに `-3`、`-4` と増えるのを防ぐため。
- desktop：`apps/desktop/src-tauri/src/library.rs`
  - `library_list(path) -> LibraryView { path, name, stamp, presets, compounds }`。読み込みは `files::for_read`（`.show.json`、サイズ上限）と `omoiiro_store::load_path`（migration 込み）。失敗は `files::load_error`（`{code, message, details}`、JSON Pointer つき）。
  - `library_preview(path, kind, id)`：読んだショーで `material_preview::sample`。
  - `library_import(path, kind, id) -> EditorView`：`InsertPreset` / `InsertCompound` を `editor_apply` 経由で適用（Runtime 動作中も同じ経路）。既にある内容なら履歴を積まず、既存 ID を `outcome` に入れて返す（`editor::current_view`）。
  - `library_add(path)`（読めるファイルだけ登録）/ `library_remove(path)`：端末設定をそのまま保存する（ポート検査は通さない）。設定ファイルが読めなかった場合は保存を拒否する。
  - キャッシュ：`LibraryState`（path と mtime / size が同じなら再利用、最大 4 ファイル）。
- GUI：素材欄の上部で「このショー」「ライブラリー」を切り替える。ライブラリー側は登録した全ファイルの素材を一覧し、カードに出所ファイル名を出す。
  - 操作は「このショーに取り込む」と「レイヤーに配置」（取り込んだ新しい ID で既存の配置処理を実行）。「効果を編集」「分類を保存」「お気に入り」はライブラリー側では無効。
  - 「ライブラリーを追加…」「外す」は素材欄の中にある。未登録のときは雛形 `shows/omoi-iro-live-template.show.json` の登録を案内する。
  - 読み込みに失敗したファイルは、その行にだけ `role=alert` を出す。ほかのファイルは表示を続ける。
- 試験：`edit.rs` の `library_compounds_import_with_their_presets_once`、`library.rs` の `lists_old_files_and_reports_broken_ones`（0.1.3 fixture、壊れたファイルの Pointer、キャッシュ上限）と `template_materials_import_once_into_a_new_show`（雛形の全素材を新規ショーへ取り込み、2 回目は何も増えない）、`settings.rs` の正規化と旧ファイルの読み込み。

## 再生操作バー

- 状態の集約：`apps/desktop/src/previewStore.ts`。プレビュー Channel の購読は 1 本で、frame・PreviewInfo・エラー・Runtime の手元時計を `useSyncExternalStore` で配る。毎フレーム描き直すのは購読している部品（操作バー、Playhead、LedPreview）だけで、タイムライン全体は描き直さない。
- 部品：`apps/desktop/src/Transport.tsx` の `TransportBar` と `Playhead`。ツールバーの直下、警告一覧の上に置く。
  - 先頭へ／再生・一時停止／停止（先頭へ戻して停止）、位置 `m:ss.ff`（30 fps）/ 長さ、テンポ、表示元のバッジ。
  - Space：再生・一時停止。input / select / textarea / button にフォーカスがあるときは無視する（ボタン上の Space はクリックになるため）。
  - ルーラーのクリックで位置を移動する。複合素材の中ではバーを無効にする。
- プレビューの再生・位置移動は、表示元が実機出力なら手元の時計（独立プレビュー）へ切り替えてから行う。Live と実機の位置は変えない。
- ショーを編集用に開くと自動で `preview_open` を呼ぶ。Runtime が停止中なら「手元で再生」表示にする。
- `preview_open`（`apps/desktop/src-tauri/src/preview.rs`）：編集中のショーと同じファイルなら未保存の編集を含めて使う。空のパスは保存前の新規ショーを使う。

## 手元の時計（A21）

- `omoiiro_runtime::session::TimeSource { Live（既定）, Local }`。`SessionConfig.time_source`、`StartRequest.time_source`（`#[serde(default)]`、既存の呼び出しは live のまま）。
- `Transport::new_local(cfg, length_us, bpm)`（`crates/omoiiro-runtime/src/sync/transport.rs`）：`LocalTime { clock: LocalClock, bpm }` で snapshot を合成する。
  - 常に Locked。再生中は Follow、停止中は Hold で位置を保持して表示する（Live の `stop_behavior: blackout` は適用しない。設計承認済み）。
  - 長さに達するとループする（`LocalClock` の wrap）。拍は `position × bpm / 60`。`mtc_label` は origin と show_time から作る。
- `FollowSession::start`：local のときは bridge の UDP 受信（bind もしない）、MIDI Clock 入力、Link、MTC 出力を開かない（MTC は note を出す）。Render、LED、安全上限、操作経路（control_in → control_out）、Note Off、切断からの復帰は従来の経路のまま。
- 操作：`FollowSession::local_play / local_seek / local_set_bpm`（20〜999 bpm）。Live 追従中は理由つきで拒否する。`submit_show` で編集を反映すると、ループ長も更新する。状態は `SessionStatus.time_source` と `local: Option<LocalTransport>`。
- desktop：`runtime_transport_play / seek / bpm`（`apps/desktop/src-tauri/src/lib.rs`）、`StatusDto.time_source`（停止中は null）と `local`、端末設定 `last_time_source`（開始に成功したときに保存する。`settings::remember_time_source`）。
- GUI：演奏タブの「開始」の横で時刻源を選ぶ（初期値は `last_time_source`）。時刻源タイルは「手元の時計（再生中／停止中）」、拍源タイルは「手元（N bpm）」と出す。
- 操作バーの接続：`previewStore.clockView()` が「いま操作している時計」を決める。Runtime が local で動作中なら Runtime の transport command を使い、バッジは「実機出力（手元の時計）」、テンポも変えられる。それ以外はローカルプレビューを使う。local で開始すると、LED プレビューの表示元を実機出力へ切り替える。
- 試験：`session.rs` の `local_time_source_plays_seeks_and_stops_dark`。fake backend で、起動直後は Hold、再生で時刻とフレームが進み LED Out へ送信がある、一時停止して seek すると時刻が一致する、bpm の範囲、MTC が出ない、stop で LED の shutdown が最後に送られることを確かめる。既存の Live の試験には、local の操作を拒否することの確認を足した。
